# LiteParse

The capture hook calls upstream LiteParse WASM 2.15.1 for original PDFs and PaddleOCR.js 0.4.2 with packaged PP-OCRv5 mobile models for images and LiteParse's scanned/image-region OCR callback. It runs after all acquisition and background observers finish, so Google exports and provider downloads are included. It selects successful, nonempty original HTTP PDF/image responses, deduplicates input bodies by their recorded digest, filters tiny images, sorts by original size, and parses sequentially. Browser-printed PDFs and screenshots are excluded, matching the canonical plugin's exclusion of redundant HTML-derived files.

Each unique input produces one JSON result under liteparse, retaining text, PDF layout, positions, word boxes, metadata, annotations, structure and blocks from the actual LiteParse schema. Direct-image OCR provides Paddle's line text, region bounds and confidence. Record metadata links the result to the exact original response URL/timestamp and records its filename, MIME, dimensions, byte size and digest. There is no duplicate TXT, original-byte copy, or saved rasterized PDF page. The canonical full.html original/text comparison, filters, copy buttons and download actions are ported into React. Source images retain dimensions and replay URLs; original PDFs render with Chromium's viewer. TXT downloads are generated from saved JSON text.

ZIP, EPUB and ZIP-based Office originals are inspected recursively for PDF/image members. Results reference the original response plus its member path chain; extracted input bytes are never saved separately. Member names and CRCs are checked by the shared ZIP reader. Discovery is bounded to eight nested archives, 256 MiB per member and 1 GiB of expanded data. Partial HTTP 206 responses are excluded. Office document conversion is not part of this OCR engine.

The plugin retains the canonical configuration names. Defaults are 100 source files sorted by size, 1,000 pages, 150 DPI, a 180-second parsing timeout and a minimum image dimension of 128 pixels (skip only when both dimensions are smaller). Target pages, passwords and disabling OCR are supported. The hook has a 180-second overall budget, configurable through its existing HOOK_TIMEOUT setting. Unsupported image decoding and malformed PDFs report per-source errors. Browser OCR quality/language coverage is that of the pinned models, not every native backend.

The separate capture sandbox runs generated upstream bindings without extension APIs; removing a timed-out or aborted sandbox hard-stops its engine. Models, interpreter code and WASM are packaged, with no CDN dependency. Cards, full viewers and the standalone HTTP player read saved results and never start OCR. A source error preserves completed results and marks the hook failed.

# Experimental browser plugins

This tree is isolated from the canonical abx-plugins checkout. Each plugin owns a config.json and browser/ directory. WXT statically bundles these modules; no downloaded executable plugins are loaded.

`browser/on_Snapshot__NN_description[.bg].ts` exports an async default function receiving HookContext from src/capture/types.ts. Numeric ordering and bg/fg semantics match abx-dl. `.finite` and `.daemon` are descriptive only. Background hooks call ctx.ready(), observe events, await ctx.untilStopped(), then flush original evidence. Every hook executes in its own Worker. Stop sends an AbortSignal before Worker.terminate() after shutdown_grace. Named settings in ctx.config are shared across enabled plugins, like the canonical hook environment; HOOK_TIMEOUT remains local. Screenshot page count uses the same INFINISCROLL_SCROLL_LIMIT as scrolling. Config supports timeout (seconds), required_plugins, wait_for_plugins, wait_for_background_cleanup, and properties/default values.

Use ctx.page.evaluate(expression) or ctx.page.command(CDP method, params) for page operations. evaluate runs in the recorder's named isolated world: it shares the live DOM, but not page globals or modified JavaScript prototypes. Browsertrix and DOM inspection hooks share that isolated world; bindings are scoped to it, and navigation selects a fresh context. Do not use unscoped Runtime.evaluate commands in plugins. Event subscriptions use await ctx.page.on(method, callback). ctx.archive.fetch(url) reuses an existing response or fetches missing bytes into the shared archive. ctx.archive.addResource({kind,mime,body,metadata?}) accepts text or Uint8Array and returns a persisted reference. Return {status,summary,records,data?}; success is the default. Original acquisition metadata in data is preserved in the ArchiveResult output_json in index.jsonl; keep response bodies and derivable reports out of it. Never duplicate HTTP response bodies in generated JSON.

`ctx.archive.read(ref)` returns `{body: Uint8Array, mime, status, headers, metadata}` from the exact original stored response, resolving native deduplicated payloads. Use it to inspect fetched API responses and follow bounded pagination; return references, never a second persisted copy of their JSON. References are restricted to the current capture.

`ctx.archive.fetch(url, {method, headers, body, maxBytes, timeoutMs})` preserves actual request identity. Compatible GET/HEAD responses already in Webrecorder's ArchiveDB are reused, including pending browser requests after their commits complete. A HEAD is never invented from a GET. Explicit credentials, range, user-agent and response Vary headers affect reuse. Acquisitions serialize lookup/fetch/write per URL and method. WARC export deduplicates equal response bodies across methods; CDX remains the resource index.

`ctx.archive.fetch(url, {browserSession:true})` uses the captured document's browser session for GET exports requiring its partitioned/HttpOnly credentials. It retains the same recorder reuse, timeout, byte budget, read and reference APIs. Plugins never handle the CDP download stream.

The Python engines share `vendor/python/transport.ts` and the supported Requests adapter in `vendor/python/requests.py`. Capture transport can acquire missing responses. `createCapturedTransport` and `createArchivedTransport` resolve only recorded exchanges, retaining failures even when upstream code catches the exception. Use the captured-only variant as a completion gate before sealing; use the archived variant for all replay derivation. Do not add live-network fallbacks to viewers.

Original evidence gets a unique `urn:<kind>:<captureId>:<uuid>` resource handle; its full source URL is preserved as `sourceUrl`. The shared exporter stores its unique bytes in the owning plugin's folder (for example `screenshot/screenshot.jpg`) and records the handle-to-storage mapping in the producing ArchiveResult's output_files. Byte-identical resources share one stored body. HTTP exchanges keep their original request URLs and bodies in the normal WARC/CDX layout; neither `responses/` nor plugin folders mirror those bodies. Plugins never choose WARC locations or manage ZIP offsets, byte ranges, payload deduplication, or replay routing.

Storage follows the bytes' origin: verbatim server responses, including downloadable exports, subtitles and fragments, belong to the shared WARC. Bytes generated or transformed by the extension belong in plugin subfolders when they must be retained, or are derived on view. A plugin requesting a file does not make the server's original bytes a generated plugin artifact.

`browser/view.ts` exports an async ViewContext => ViewResult function from src/archive/views.ts. It runs only when opened, reads ArchiveReader.entries, artifact(kind), read(entry), text(entry), json(entry), or dom(), and populates its canonical plugin template. These operations work identically for HTTP payloads, generated plugin files, and deduplicated references. `archive.integrityTree()` supplies the storage hash hierarchy without requiring the hashes plugin to inspect offsets or parse indexes. HTML is sanitized by the host and rewritten with upstream Webrecorder Rewriter. Referenced images/styles/media load through the shared replay layer; never inline their bytes as data URLs or write another resource tree. Derived views never write back into the capture. Paths/types are temporary experimental integration imports and can be extracted into a package later.

An optional `browser/available.ts` exports `(context: ViewContext) => boolean | Promise<boolean>` for cards. Use the existing capture outcome, resource index and bounded header inspection; do not start extractors or read full payloads. `archive.headers(entry).image` supplies intrinsic dimensions when the archived image header is readable, without decoding pixels. Return false only when the view has no output; absent, unresolved or failed checks leave availability unknown and the card visible. Supplemental-fetch hooks reporting `noresults` do not imply an empty derived view (for example SEO still reads page metadata). Hidden cards do not remove original resources or hook diagnostics.

Final processing hooks use `wait_for_background_cleanup` to stop observers and close/drain the recorder before parsing. LiteParse runs at 68 and saves text/layout JSON; search_contents runs at 90 and saves its inverted index without raw text copies. Original HTTP documents and ZIP members remain source references. Readability and ForumDL still derive their presentations only when opened. Office document text uses the bundled upstream OfficeParser slim engine; OCR remains the single LiteParse/Paddle path.

The [ArchiveBox records](https://github.com/ArchiveBox/archivebox-js/blob/6accc97adad02ce784bcb10ec6a6aedfef6d9d7d/docs/interchange.md) use the existing Python model fields, mirrored in `shared/records.ts`. Export writes one `Snapshot` and the actual hook `ArchiveResult` rows, including output_files, into `index.jsonl`; derived-only viewers do not create successful capture results. `datapackage.archivebox` points to this hashed JSONL member.
